## Reproducible Evidence Commands

Run from `app/`:

```sh
npm run assets:nutcracker-swf
npm run assets:nutcracker-ui
npm run assets:nutcracker-actors
npm run assets:nutcracker-jpeg3
npm run assets:certificates
npm run assets:source-atlas
npm run assets:shell-reference
```

The SWF pass writes ignored proof artifacts to `app/generated/nutcracker-source-extract/full-swf-pass/`:

- `manifest.json`
- `dumps/*.placements.txt`
- `dumps/*.actions.txt`
- `dumps/*.text.txt`
- direct lossless PNG extraction records

The JPEG3 pass writes ignored repaired image proof artifacts to `app/generated/nutcracker-source-extract/direct-image-tags/`.

The shell/reference pass extracts the final valid `Nutcracker2.exe` payload, locks the `playRoom` frame and button evidence, captures projector/intro dumps under `app/generated/shell-reference-source-extract/`, and promotes correctly named intro, room, Listening Room frame, and gramophone assets under `app/src/assets/source-scenes/`.

The certificate pass extracts the appended Flash payloads from `analysis/setup/app/fscommand/n_certificate.exe` and `nc_certificate.exe`, writes ignored projector/SWF/action/text/display-list proof under `app/generated/certificate-projectors/`, and promotes only the intact Nutcracker-specific sprite id `0018` certificate to `app/src/assets/nutcracker-source/nutcracker-club-certificate.png`.

The actor promotion pass reads the ignored SWF output and writes committed actor assets to `app/src/assets/nutcracker-source/song#-track#-actor.png`.
It intentionally skips copying when ImageMagick reports the selected generated PNG is pixel-equivalent to the committed target, because `swfextract` can rewrite identical indexed PNG art with different bytes.

The UI promotion pass currently copies source UI bitmap evidence such as `song1__song/lossless-39.png` into correctly named committed assets like `song-curtain-scallop.png`. It also extracts/renders recoverable song `courtain` child shapes id `0038`, `0040`, and `0041` from base sprite id `0042`, applies the source `0040` CXForm add `0 102 255 0`, and promotes `song-curtain-fill.png`, `song-curtain-curve-cxform.png`, and `song-curtain-stars.png`; extracts/renders source song-control shapes `0119`, `0126`, and `0113` for `song-control-help-body.png`, `song-control-button-body.png`, and `song-play-again-button-body.png`; extracts/renders `nutchooser.swf` background shapes id `0016`, `0017`, and `0018` from composition sprite id `0021`, applies the id `0017` source CXForm add values `143 60 -10 0`, recreates the JPEG3-backed shape id `0020` from bitmap id `0019` with CXForm `mul 0 0 0 1` / `add 255 51 153 0`, and promotes `chooser-hallway-fill.png`, `chooser-hallway-portal-cxform.png`, `chooser-hallway-vector.png`, and `chooser-hallway-tint-cxform.png`; extracts/renders sprite `0068`, trims it, applies the root placement CXForm, and promotes `chooser-instruments-cxform.png`; extracts/renders `nutchooser.swf` shape id `0201` to promote normal visible `chooser-help-button-art.png`; extracts/renders `nutchooser.swf` shape id `0205` and text id `0204` to promote the composed normal visible chooser `quiter` as `chooser-exit-button-art.png` plus `chooser-exit-label.png`, because text id `0203` is the blue `buttonOFF` EXIT label and full button id `0206` currently renders as a 1 x 1 placeholder; extracts/renders chooser `magicKey` sprite id `0213` in a translated wrapper and promotes `chooser-magic-key.png`. ## Things Already Learned The Hard Way

- M08 extraction is centralized in `npm run assets:m08`. It hash-locks 34 SWFs plus 13 Alice and 33 Nut House source-runtime captures, parses actions/placements/text, extracts 112 top-level JPEG3/lossless images, 3 verified root streams, 205 standalone sounds, and 77 runtime companions, and writes the durable manifest under ignored `app/generated/m08-source-extract/`. Backup files and alternate Children's Album WAV copies stay in the authoritative source tree rather than being duplicated into runtime assets. The script preflights every source/companion, SWF hash, and all 46 capture hashes before removing only its owned generated/promoted roots for rebuilding. Use `docs/m08-mini-games-source-map.md` and `app/src/assets/m08-source/`; do not reconstruct these families from filenames or generic game conventions.
- A SWF DefineSound id is not a semantic game id. Read `EXPORTASSETS` and the corresponding `attachSound` calls before connecting extracted `sound-N.mp3` files. M08 caught three concrete traps: Loopy visible tracks 1..8 map to sound ids 9..2, Orchestra `s1..s18` maps to `[17,11,14,19,8,13,9,3,15,7,16,18,1,2,5,6,12,4]` with `badInst` at 10, and Nut House mirror previews/feedback use room-local export maps. Keep raw provenance assets committed, but narrow eager Vite globs to semantic aliases and actually used audio so evidence files are not shipped in the desktop bundle.
- An `swfextract` inventory line saying `MP3 Soundstream` is not proof that `swfextract -m` can produce a file. Children's Album, the Loopy games, Alice 10-12, and the Nut House rooms can report `Soundstream is not mp3 (2)` or `Didn't find a soundstream`; record `blocked` unless the target exists and is hashed. Continue with standalone `DefineSound` extraction rather than failing the entire source audit.
- M08 root renders are mostly diagnostic failures, not complete scene evidence. Children's Album, Orchestra, all eight Loopy boards, all 12 Alice puzzle boards, and all eight Nut House rooms crash with `SIGSEGV` or produce no usable PNG. Toy Soldiers' root probe exposes its green field, first cyan moving-shape frame, staff, and unhidded feedback flashes but omits every button-backed soldier/control; isolated sprite id `0031` renders transparent because local `swfrender` cannot resolve button id `0030`. Do not replace it with invented characters: `swfdump -u` proves id `0030` uses recoverable blue-circle shape id `0029`. `npm run assets:m08` renders centered 2048 px wrappers for shapes `0020`, `0021`, `0024`, `0025`, `0027`, `0029`, and `0032`, resizes them to their SWF bboxes, and promotes source text ids `0034`/`0037` from wide wrappers. Waltz's 550 x 400 root gradient is also promotable as an explicitly incomplete source-derived surface; the Alice chooser renders only an incomplete ring. Inspect and promote child evidence, attach exact DOM fallback provenance, and do not call partial root outputs full scenes.
- For Alice specifically, the official Ruffle 0.5.0 self-hosted runtime resolves the complete displays that SWFTools cannot. The successful probe used `ruffle-0.5.0-web-selfhosted.zip` from the official release, a temporary `python3 -m http.server 8099 --bind 127.0.0.1`, direct `game_XX.swf` playback for each 800 x 600 root, and the chooser after its approximately 40-second introduction. Full-page browser captures were cropped to the 800 x 600 player and saved under `analysis/setup/app/games/aliceswf/recovered-renders/`; `assets:m08` hash-locks and promotes them rather than rerunning an unpinned network tool. Preserve all 12 source-local stage names even when files are identical. Chooser `bodyAndHand` sprite id `0151` renders in a centered 2048 wrapper with false distant fragments; after `-trim +repage`, crop `132x131+960+960` to recover the actual clock control. Gear id `0098` renders intact at 182 x 182. Sprite `0151` randomizes a permutation of toy frames 1 through 4, chooses a random initial position, and uses snap angles `[−90, 0, −270, −180]`; never model this as zero-based `0..3` state because frame 4 then becomes unreachable and solution frame 1 is mislabeled. The current DOM fallback cycles the four valid frames while stable captures retain scene art, so the random angle mapping, live toy-frame changes, correct-state character/gear animation, tweened chooser/clock animation, and exact pointer gesture remain manual-review gaps.
- Toy Soldiers' `randomize()` name is misleading: it does not choose new random values. It snaps the authored root y positions to `y_coords[i] = 300 - (21.5 * i)`, yielding initial slots `[7,4,1,8,5,2,8,10]`. Its pitches cover 0 through 10, not only 1 through 8, and map to DefineSound ids `[13,1,3,5,7,9,11,13,15,3,5]`. Preserve those boundaries and cancel the timed eight-step march when navigating, resetting, or stopping scene audio.
- Do not wire Toy Soldiers `Play Music` as the current-position checker. Button id `0035` starts child `play_correct`, whose `play_by_num(i)` reads root `correct_note[i]`; soldier button id `0030` release is the path that snaps the current `y_loc`, stops sounds, and starts root `march`. The latter calls `march_soldier(soldier_i, i)`, shows the correct/wrong flash, and accumulates `wrong_notes`. Keep the two eight-second sequences distinct and test interruption because both reuse the same visible control surface and timers.
- Waltz has no recovered root play button. Its 785-frame timeline and sound stream start immediately, so the remake should start bundled `MP3Wedding3.wav` once on route entry and stop it on route exit. Visible provenance copy, a modern `PLAY WALTZ` button, or a looping track changes the recovered behavior.

Keep the correctly named source-local promotions as provenance, but do not claim exact color/display-list parity until the nested transforms can be replayed. Identical pixels or hashes across Alice puzzle groups do not authorize misleading shared names: games 01-03, 04-06, 07-09, and 10-12 are four byte-identical groups, yet each runtime import remains puzzle-local.

It validates the source atlas/rights metadata, runs the production build, uses Tauri's macOS `signingIdentity: "-"` to seal the complete app bundle with an ad-hoc signature before creating the DMG, verifies that signature, read-only mounts the DMG, proves the mounted app matches the fresh app bundle, checks metadata/architecture, counts bundled media, and writes an ignored artifact manifest. ### Live projector at the Ruffle boundary (Stage 2/3, JIP-1536 to JIP-1538, 2026-11-06)

- The launcher and the music room are the unmodified projector (`projector-nutcracker2.swf`, SHA-256 `b6a36777…4c2b`) playing interactively in the Ruffle layer. Don't rebuild projector scenes in the DOM. The static capture and hotspots under the layer are only the fallback for when Ruffle fails, so they get `tabindex="-1" aria-hidden="true"` while the projector is live.
- Code: `app/src/flash/projectorBridge.ts` (boundary, stand-in movie, start-frame patch) and the projector state machine in `syncSourceSwf()` in `app/src/app.ts`. `projectorPosition` is `launcher`, `room`, or `away`, where `away` means the projector is parked at root frame 2383 with a game "loaded" in `_level1`.
- Every projector request is answered by the shell. Ruffle loads with `base: <origin>/__projector/`, `allowNetworking: "all"` and `openUrlMode: "allow"`. A `window.fetch` wrapper answers everything under that base, and nothing reaches the network:
  - `games/data/gamekeys.txt` is built from the progress store.
  - Room `loadGame` movies (paths in `projectorGameRoutes`) get a generated stand-in SWF while the shell opens the matching route.
  - `flute_intro.swf` (MFBtn) switches to the fitted Stage 1 intro.
  - Anything else gets a 404. Example: `games/keycontroller.swf`, which the projector loads into `_level2` before `playRoom`, is not in the recovered install.
- The Ruffle v0.5.0 core calls `window.fetch` and `window.open` on the global window through wasm-bindgen glue. Both can therefore be wrapped from JS. A `getURL("http://…")` with an **empty target** is refused ("opening URLs in the current tab is prevented by script access"), and with `allowScriptAccess` it would call `location.assign`, which can't be wrapped. That is why the runtime retargets the projector's one website `getURL` to `_blank` (`patchProjectorWebsiteTarget`). A `_blank` target with `openUrlMode: "allow"` reaches `window.open`.
- Ruffle 0.5.0's v1 API (`player.ruffle()`) pauses with `suspend()` and resumes with `resume()`. It has no `pause()`. Fakes in tests must use the real method names: a fake with `pause()` hid this bug once. The wrapper sends it to `openExternal`, guarded against re-entry because the browser-preview `openExternal` itself calls `window.open`. Never let it reach the webview.
- How the original games returned, which the stand-in reproduces: set `_level0.gameKeyN = 1`, call `FSCommand:exec saveKeyN.exe`, then `_level0.gotoAndPlay("comeAgain")`. Root frame 2384 `comeAgain` unloads `_level1`, shows `_level0`, and frame 2386 jumps back to `playRoom`.
  - The stand-in is a 3-frame SWF 6. It long-polls `__shell/return.txt` into `_level1`, which the shell answers with `ret=1&gameKey1=…` when the route returns to `main-menu`. It then copies the nine keys into `_level0` and calls `comeAgain`.
  - Check it with `swfdump -a` on the bytes from `buildProjectorReturnStubSwf()`.
- `fscommand` reaches the shell through `ruffle().addFSCommandHandler`. `quit` calls `exitApp`. The holdToReset `exec reset*.exe` helpers map to the progress-store resets. Match them case-insensitively, because the projector says `resetgameKeys.exe` while the install has `resetGameKeys.exe`.
- Two original behaviours worth knowing:
  - Website YES runs `getURL` on `warningMSG_mc` frame 3 and then `FSCommand:quit` on frame 10. The original opened the site and closed the CD.
  - The room's own EXIT sets `doExit`, plays the `exitNow` outro (root frame 2389), then quits.
- Ruffle can't start at a label. To start in the room (route map, fallback Play button), the runtime fetches the projector once and patches only the frame-1 `ActionGotoFrame` operand in memory: opcode at byte **79520**, operand bytes 79523-79524, value 1267 → 2143 (`nutIni`). The asset gate asserts this offset. The Alice preview docs once said "79524-79525", which was off by one.
- Suspend, don't destroy: when a game route opens from the room, the layer is hidden (`data-suspended`) and Ruffle `pause()`d. Returning calls `resume()`, then answers the stand-in.
- Tests: happy-dom has no asset server, so `src/tests/setup.ts` keeps `.swf` fetches pending (inert, like the inert RufflePlayer). The boundary is driven through `window.fetch(projectorBaseUrl() + path)` with a fake layer in `src/tests/projectorBridge.test.ts`.
- Window probes:
  - On macOS, a `tauri dev` window behind other windows reports `document.hidden === true`. WebKit then stops painting it, so `screencapture -l` returns black, and Ruffle pauses itself while hidden.
  - Bringing the window to the front steals Marcus's focus. **Don't run window or screenshot probes for this project without asking Marcus first.** Prove behaviour with the source dumps plus vitest on the boundary hooks, and ask Marcus to look at the visuals himself.
  - The one capture taken (launcher, live in Ruffle, `playing` about 6 s after launch) matched the source frame.
- Don't add `await import()` at the top of `main.ts`. Top-level await lets `DOMContentLoaded` fire before `createAppShell`'s listener is registered, and the app never mounts.

- Keep generated proof output under `app/generated/` ignored unless Marcus explicitly asks to persist a generated artifact.
- Commit small source-backed increments with evidence in `docs/nutcracker-song-source-map.md` or this knowledge base.

- **FSCommands need script access (Ruffle 0.5.0).** `web/src/builder.rs` installs the JS FSCommand bridge only when `allowScriptAccess` is true **and** `allowNetworking` is `"all"`. Otherwise `core/src/avm1/fscommand.rs` logs `Unhandled FSCommand` and drops it, and `addFSCommandHandler` handlers never fire. The web player has no quit handling of its own. The vitest fakes call the handler directly, so they could not catch this. Marcus found it on 2026-11-06: EXIT, then YES, left him on the credits with no way out. The interactive load options now set `allowScriptAccess: true`. That is safe only because the projector's one empty-target `getURL` (the website) is retargeted to `_blank`. Before turning on script access for another source movie, grep its actions for `GetUrl` with an empty or `_self` target: with script access Ruffle sends those through `location.assign` and the app navigates away.
- **Help guide (trumpet) looks like a freeze.** It plays a narrated tour of about 2 min 45 s behind a full-stage, hand-cursor-free `noAction` button. That is the original behaviour; any click ends it.
- **Original games run inside the projector (2026-11-06).** Marcus asked for every activity to be the original movie, not a remake. The boundary serves `public/projector-install/` (mirrored by `npm run assets:projector-install`) for any path in its `index.json`. Real games load into `_level1` and return through `comeAgain` on their own, so the shell no longer navigates for room games. Look up paths **lowercased**: `normalizeProjectorPath` lowercases, and the index keeps the CD's spelling for the actual fetch. Some exec helper names are built at runtime (`"saveNutDoor" + n + ".exe"`), so grep the dumps for the prefix, not the full file name. To dump every game's actions, run this from `analysis/setup/app`: `find games activities -name '*.swf' -not -path '*/recovered-renders/*' | while read f; do swfdump -a "$f" > "<scratch>/$(echo $f | tr / _).txt"; done`
- **Testing fetch stubs around the boundary:** don't `vi.spyOn(window, "fetch")` before `createAppShell`.
